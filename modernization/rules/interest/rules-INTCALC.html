INTCALC monthly interest - business rules review board

Once a month the scheduler runs job INTCALC (folder MONTHLY-InterestCalculation, after CLOSEFIL and before COMBTRAN). Its only step, STEP15, runs CBACT04C with a cycle date given as a literal parameter (2022071800). The program reads every transaction-category balance of every account in key order. For each balance it looks up the annual interest rate for the account's disclosure group, transaction type and category, falling back to the DEFAULT group when the account's group has no row. When the rate is not zero it computes one month of interest (balance x rate / 1200), cuts it to the cent without rounding, and writes one interest transaction (type 01, category 0005, source System) to a new SYSTRAN generation, identified by the cycle date plus a running number. When it moves on to the next account it adds the account's total interest to the current balance and resets the cycle credit and debit totals to zero. Because of how the loop is written, the last account in the file gets its interest transactions but never gets its balance updated. Fees are named in the job comment but not implemented. Any missing account, card cross-reference or DEFAULT rate, or any file error, stops the run with abend U999 after whatever was already written.

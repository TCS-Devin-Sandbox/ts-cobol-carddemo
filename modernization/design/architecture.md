## A1 · Target boundary and ownership

One Java 21/Spring Batch job `interestClose`, PostgreSQL 15, replacing **only** INTCALC.STEP15 / CBACT04C. No web/API or change to posting, fee assessment, CICS, scheduler, combined-transaction processing or Db2 reference maintenance. Proposed module: `interest-batch/` (Maven). New application schema `interest`; Spring Batch JDBC metadata is in `interest_batch`. The existing `carddemo.transaction_type` and `carddemo.transaction_type_categor` from [db/postgres](../../db/postgres/01-transaction-type.sql) remain owned by transaction-reference maintenance; no foreign keys, grants or migration changes from INTCALC (TN-08).

| Component (single writer) | Tables it owns/writes | Contract |
|---|---|---|
| Snapshot intake | `interest.snapshot`, `interest.account_input`, `interest.card_xref_input`, `interest.category_balance_input`, `interest.disclosure_rate_input` | Validates provenance, bytes, field widths, key uniqueness and reconciles the four inputs; seals an immutable, coherent snapshot only after validation. Base and AIX view are the same xref source. |
| Job coordinator | `interest.run` | Immutable run identity and parameters after start; lifecycle `READY → COMPUTING → COMPUTED → RELEASED`, or `FAILED/HELD`; release transition only on verified bridge receipt. Lock a single live cycle and publication scope across incl. unknown outcomes; shadow rehearsal isolated. |
| Calculation writer | `interest.interest_tx`, `interest.account_delta`, `interest.run_checkpoint` | Appends private fixed-layout output rows and before/after account deltas; advances checkpoint only atomically with these rows. Last account emits transactions, never a delta (INT-Q02). |
| Publish adapter | `interest.publication` | Per-run state/receipt ledger for payload checksums, destination, prior/current absolute generations, delta preconditions and matching mainframe operation ID. A second attempt must first resolve any unacknowledged external effect. |
| Spring Batch repository | `interest_batch.batch_*` | Job/step executions and operational context. Business restart position lives in `interest.run_checkpoint`, not in logs or an independently committed Spring offset. |

Operations may inspect/report but does not update business tables by hand. Grant intake/compute/publish only their own write permissions and required reads. Snapshot and run artifacts are private; no ordinary mainframe job reads them. Retain immutable input, preimages, manifests and receipts through the approved recovery window; mask identifiers in ordinary logs and use synthetic data in this repo. Legacy-compatible SYSOUT for parity may contain raw records and is a restricted artifact.

## A2 · Job input, order and return contract

1. **Validate/load:** Bind snapshot ID and digests, mode (shadow or live), target feed/cycle, exact 10-byte-compatible PARM and source codec profile. Keep the observed fixture PARM `2022071800` (INT-H02); do not infer a production substitution or interpret it as a timestamp. Verify raw counts, hashes and decoded totals before sealing. Duplicated source primary keys, quarantines, changed provenance and unexpected record geometry prevent readiness. Empty valid TCATBALF completes without affecting accounts.
2. **Compute:** Read TCATBALF in original composite key order (legacy encoded unsigned-byte order, not database locale or heap order). Each account group triggers keyed account and first-AIX-card reads even when the rate is zero. Try the exact key then space-padded DEFAULT on missing group, recording the legacy diagnostics; do not fall back from zero. Use exact decimal arithmetic and literal percentage denominator 1200. Keep COBOL receiver widths at every assignment/addition (INT-Q01/INT-H05), negative rates/amounts (INT-Q03/INT-H07), zero when a nonzero rate yields 0.00 (INT-Q04), no fees (INT-H01), no status/date filters (INT-H04), no account scan or blanket reset (INT-Q06), no TCATBALF clears (INT-H09). Assign run-wide six-digit suffix from emitted-record ordinal modulo 1,000,000 (first 000001); export by ordinal, not ID. Capture the legacy local wall clock **per emitted transaction**, both fields from the same reading, hundredths plus four zeros; fixture clock is frozen. Commit an account delta only when the existence of another account in TCATBALF is known; delta has only current balance and the cycle totals changed. Preserve unchanged fields and filler.
3. **Reconcile/package:** Replay the full post-image from input plus deltas for fixture comparison; for live send conditional patches plus the fixed-length, ordered 350-byte SYSTRAN records and a manifest. No ready/release packet is emitted on any compute failure. Adapters produce parity SYSOUT and status (`0` normal, U999 domain result / RC 12 in the harness on legacy failures, TN-01/04/07/09); infrastructure errors also fail closed with separate diagnosis. An error artifact distinguishes failed private work from a successful empty generation.
4. **Publish/handoff:** Outside the calculate transaction and not in a retrying chunk; see A4. Shadow never reaches live data. Live completion is held until mainframe receipt and fence checks. Only then emit the existing INTCALC success condition to unlock COMBTRAN.

## A3 · Transaction and restart boundaries

| Boundary | Commit point | Failure, retry and exposure |
|---|---|---|
| Intake | Rows can load in private batches; validation + seal flips readiness in a DB transaction | Partial intake is not selectable. Resume only by verifying exact manifest or rebuild a new attempt; never mutate sealed rows. |
| Compute | One ordered account group per PostgreSQL transaction. For a nonfinal group commit staged transactions, its delta and next-key/last-account/last-ordinal checkpoint together; at EOF commit last group's transactions/checkpoint without delta. One runner locks the run and checkpoint. | Crash before commit rolls back the whole group; after commit the group is not replayed. Seek from the committed key on the same sealed snapshot and config, not a file offset or a recomputed transaction clock for committed rows. Uncommitted attempts have no published timestamp. Hold `FAILED` work, retain diagnostics; resume only by explicit authorization for private target work, never a second live launch. |
| Package | Persist `COMPUTED` and verified checksum/record counts from immutable staged output; external package not eligible until complete and validated | Recreate by run ID/hash; checksum mismatch holds. Stage IO failures do not expose partial account patches or generation. |
| Publish | External host steps and durable receipts; no XA between PostgreSQL and VSAM/GDG | Preflight all account preimages under fence before mutation. Track preimage/postimage per key in the host journal; resolve uncertain write by reading both guarded field values and record fingerprint; mixed/unknown state stays fenced. Inspect actual absolute GDS/digest before retry or rollback. Do not blindly reapply an interest delta, catalog a second generation or rely on MAXRERUN. |

Job restart identity includes `run_id` tied to snapshot/digests, cycle/PARM, feed, mode, codec, build/rule revision and clock profile. PostgreSQL transaction writers use the same data source/manager for staging and checkpoint. A unique live release claim per destination/cycle prevents starting a second writer or a fallback while the first has an unresolved effect. Assessment of error-path equivalence distinguishes matching RC/diagnostics from legacy's partially visible output; proposed design contains partial work, not a promise to recreate it. INT-H06 remains OPEN: legacy fallback stays manual restore; private technical recovery does not approve unattended live restart or recovery.

## A4 · Mainframe coexistence and cutover contract

The [manifest](../streams/interest/manifest.json) proves folder conditions `CLOSEFIL → INTCALC → COMBTRAN → WAITSTEP → OPENFIL`, not writer exclusion, cross-folder ordering, external trigger absence, deployed CBACT04C binding or duplicate JOBISN runtime handling. Keep all four neighbours. Require scheduler/CICS/host owners to establish the effective fence (including the separate CA7 daily run, CICS including any shared AUTH regions and DISCGRP refresh/setup/restore paths); abort before publication if it is not observed. DISP=SHR is not a lock protocol.

| Legacy interface | Surviving participants (illustrative; see manifest inventory) | Coexistence protocol |
|---|---|---|
| ACCTDATA KSDS | POSTTRAN and CICS COACTUPC/COBIL00C write; CREASTMT/FEECALC and CICS read; ACCTFILE can rebuild | Host remains master. Under approved fence, snapshot and capture before-image; only cutover bridge can apply changes for this cycle. Compare exact original record fingerprint, patch the three fields and verify post-image; do not wholesale reload the snapshot. Fence readers too where consistency with the release is required. |
| TCATBALF KSDS | POSTTRAN RW; TCATBALF can rebuild; PRTCATBL candidate | Host remains master. Read a consistent snapshot, never reset or write back. Hold/reject if changed between capture and controlled publish. |
| CARDXREF KSDS / XREFFIL1 path | XREFFILE rebuilds base/AIX; POSTTRAN, CREASTMT, TRANREPT and CICS read | Export base and authoritative alternate-key first-return evidence at the same capture point. Keep nonunique account association. No Java update to either interface. |
| DISCGRP KSDS | Weekly DISCGRP deletes/defines/loads independently | Freeze refresh through capture/live commit; checksum/generation proof required. Java only reads the snapshot. |
| SYSTRAN / TRANSACT | COMBTRAN reads `SYSTRAN(0)` with backup input and loads TRANSACT VSAM; see COMBTRAN STEP05R/STEP10 | While downstream is held, stage bytes privately and apply verified account patches; verify then catalog exactly one normal 350-byte `SYSTRAN(+1)`, retain its absolute name/digest, and prove it resolves as (0) for this handoff. Preflight duplicate ID/other-producer risks including backup input; do not collapse duplicate IDs or release an ambiguous generation. |

For trial/shadow, use cloned or sealed equivalent pre-run inputs; the legacy run alone writes live. For cutover, select one engine **before** any output is visible and hold the exclusion window through receipt/handoff. Before publish the packet can be discarded and legacy run once from the unchanged baseline. After any external mutation keep downstream held and reconcile under fence; restore only journaled applied account changes and quarantine/restore the exact generation per host runbook, then recheck previous pointer, before-images and counts before legacy runs once. After downstream consumption, never rerun automatically: contain and reconcile downstream TRANSACT and subsequent consumers, then use Operations' approved incident recovery. The fence, GDS recovery, binder proof and approval remain release prerequisites; this design does not invent host commands or claim runtime evidence.

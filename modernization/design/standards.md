# How the interest conversion will be reviewed

**PROPOSED · Owner: Target architect. Conversion and runtime parity have not been run under these standards. [INT-01, the pilot](tickets/01-pilot.md), is their first test.**

The interest close replaces INTCALC STEP15 only. It calculates monthly interest from category balances, writes interest transactions, and proposes changes to eligible account balances and cycle totals. The [conversion skill](../../.agents/skills/interest-conversion-standards/SKILL.md) governs every ticket. This page summarizes what reviewers should expect to see.

## Standards at a glance

- **S01** · Start with the ticket and rules, use the architecture and data map for the target shape, then read the COBOL cited by each rule.
- **S02** · Judge results against recorded legacy output and report differences between the code and written rules to the decision-register owner.
- **S03** · Give Java business operations and typed outcomes for rate lookup, group completion and errors.
- **S04** · Give the five layouts immutable business records with copybook names at the mapping.
- **S05** · Read ordered groups, process interest rules and stage writes through Spring Batch, committing each group's work and checkpoint together.
- **S06** · Constructor-inject dependencies and keep mutable account and sequence state scoped to the group or run.
- **S07** · Use exact decimals, cut toward zero at the cent boundary and preserve each receiver's digit limit.
- **S08** · Keep the file encodings, signs, byte widths and preserved filler at the codec boundary.
- **S09** · Inject the cycle parameter and wall clock separately so IDs and timestamps retain their distinct sources.
- **S10** · Keep each quirk or OPEN decision in one named implementation point with a rule-named test.
- **S11** · Send contradictions and unproven host outcomes to the owners while keeping the register OPEN.
- **S12** · Interpret each file status in context and map failure to its Java outcome, step result and diagnostic.
- **S13** · Restart only eligible private work at its committed checkpoint and reconcile uncertain host writes under the fence.
- **S14** · Keep raw legacy SYSOUT in restricted parity evidence and account data out of ordinary logs.
- **S15** · Give each rule a named test against independent expectations, using listed fixture cases and synthetic cases for gaps.
- **S16** · Verify integration with PostgreSQL 15 in a container and compare recorded fields, SYSOUT and RC alongside separate byte checks.
- **S17** · Freeze legacy source, fixtures, goldens and the comparator.
- **S18** · Preserve shared interfaces and explain new dependencies in the PR.
- **S19** · Use synthetic data in development, tests and review evidence.

## Three before / after examples

### Calculation · INT-R01 and INT-Q01

**COBOL.** Lines [462–468](../../app/cbl/CBACT04C.cbl#L462-L468) compute `(TRAN-CAT-BAL * DIS-INT-RATE) / 1200` into a two-decimal receiver, then add that stored amount to the account total. In i02, 1,235.50 at 12.00% yields 12.355 before assignment and a recorded transaction of **12.35**. The first account ends at **1,247.85**.

**Java after conversion.** Multiply the exact decimal balance and percentage, divide by 1200 into scale 2 with `RoundingMode.DOWN`, apply the receiver width, and accumulate the resulting 12.35. The fixture checks the transaction amount and account post-image independently.

### File loop · INT-R02/R03/R04/R09

**COBOL.** Lines [188–217](../../app/cbl/CBACT04C.cbl#L188-L217) and [325–347](../../app/cbl/CBACT04C.cbl#L325-L347) read TCATBALF in key order, display each record and fetch the account and card on a new account. Lines [415–460](../../app/cbl/CBACT04C.cbl#L415-L460) try the exact rate, switching to DEFAULT on status 23. In i04, the PLATINUM miss produces both diagnostic lines and DEFAULT yields **17.50**. In i03, an exact zero rate skips the record's interest transaction.

**Java after conversion.** Read account groups by encoded key from the sealed snapshot. Resolve the account and AIX card once per group. The processor handles an exact, fallback or zero rate, and the writer commits private results and the checkpoint together. Preserve the order of the balance lines and rate diagnostics in parity SYSOUT.

### Last-account quirk · INT-Q02

**COBOL.** Lines [194–222](../../app/cbl/CBACT04C.cbl#L194-L222) update the previous account only when a different account is read. The EOF read skips the apparent final-update path. In i01 the final account emits **37.00** of interest and keeps its **2,400.00** current balance and **2,400.00** cycle credit. The preceding account is rewritten to **1,010.00** and its cycle totals are reset.

**Java after conversion.** Use lookahead to distinguish a next account from EOF. Stage the prior group's balance/reset delta only when a next account exists. At EOF, stage the final group's transactions and checkpoint without an account delta. Verify the untouched row against the recorded post-image.

## What is still to be confirmed

- **Target architect** confirms the [skill](../../.agents/skills/interest-conversion-standards/SKILL.md) against INT-ARCH and INT-MAP. INT-01 exercises the standards first against i01 on PostgreSQL 15. INT-06 supplies seven-case technical parity and a simulated handoff.
- **Finance / card operations and interest policy** review the INT-Q03 wording and fixture READMEs for i01, i05 and i06. The legacy final-account rule explains why the negative i06 transaction leaves its sole account at −300.00. Business decisions stay OPEN in the [register](../rules/interest/decisions.md).
- **Application / COBOL compiler and Language Environment owners** must confirm on the mainframe the deployed Enterprise COBOL options and boundary outputs for intermediate arithmetic (`ARITH`), DISPLAY receiver overflow, binary handling (`TRUNC`), the status overlay, sign handling (including `NUMPROC`) and actual U999 diagnostics. The off-host command in `tools/build.sh` uses GnuCOBOL `-std=ibm -fsign=EBCDIC` and the local CEE3ABD stub.
- **Host data / VSAM, Card Operations and application owners** must confirm on the mainframe the actual CCSID, byte framing, sort order, sign variants/signed zero, first AIX return and status for a nonunique account key, and the initial transaction filler. The lab supports cp037 and has recorded ASCII-compatible fixtures. Production evidence must come from the host.
- **Scheduler / Operations, application and runtime owners** must confirm on the mainframe the live PARM, clock zone/DST, active writer fence, normal and abnormal GDG disposition, effective scheduler retry and downstream success condition. INT-H06 describes a partial SYSTRAN generation. JCL requests abnormal DELETE, and earlier in-place account rewrites can remain. A host failure trace must establish what actually remains available and how it is recovered. Keep uncertain effects held under [INT-ARCH A4](architecture.md#a4--mainframe-coexistence-and-cutover-contract).

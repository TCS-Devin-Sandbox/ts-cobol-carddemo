# Phase 6 — Deviations from the source

Each entry gives the source behaviour (with paragraph), the modern behaviour, and the reason. Requirement IDs refer to `requirements-ctli-cttu.md`.

| ID | Area | Source (COBOL / CICS / DB2) | Modern | Rationale |
|---|---|---|---|---|
| D-01 | PF keys → buttons | 3270 AID keys Enter/PF2/PF3/PF4/PF5/PF7/PF8/PF10/PF12 (YYYY-STORE-PFKEY folds PF13–24 to PF1–12) | One button per key with the BMS label (`F7=Page Up` …), plus keyboard shortcuts Enter/F2/F3/F4/F5/F7/F8/F10/F12 (`useFunctionKeys`). PF13–24 are not mapped. Buttons are disabled when the key is invalid (CTTU 3391 DRK → `disabled`) | Browser UX; F-key parity kept for power users |
| D-02 | COMMAREA → stateless cursor params | CTLI keeps first/last key, page number, next-page flag, pending action and the displayed rows in the COMMAREA between `RETURN TRANSID` | API is stateless: `cursor` + `direction` (+ filters) per request. The response returns `firstKey`, `lastKey`, `nextCursor` (look-ahead key, = WS-CA-LAST-TR-CODE), `hasNext`, `hasPrev`, `pageNumber`. Page number is derived (`rows before firstKey / size + 1`), so it does not wrap after 9 (source PIC 9(1), Q3). Pending U/D actions and CTTU state live in React state | REST statelessness; horizontal scaling |
| D-03 | CTTU upsert semantics | F5 save always runs `UPDATE` then `INSERT` on SQLCODE +100 (9600 → 9700), for both edit and add | `PUT /{trType}?upsert=true` reproduces UPDATE-then-INSERT (201 when inserted) and the edit page uses it for existing rows. The add path (from not-found → F5) uses `POST`, a plain INSERT, so a key created concurrently is reported as a duplicate instead of silently overwritten. `PUT` without `upsert` is the CTLI update-only path (404 on +100) | Clear REST semantics; the -803 duplicate path becomes testable (it was a race-only path in the source) |
| D-04 | Duplicate-key message | 9700 builds `Error inserting record into: TRANSACTION_TYPE Table. SQLCODE:` + the **stale** SQLCODE of the preceding UPDATE (`100`) + SQLERRM (Q6) | `409 DUPLICATE_KEY` `Error inserting record into: TRANSACTION_TYPE Table. SQLCODE: -803` | Report the real DB2-equivalent code; SQLERRM text is DB-specific |
| D-05 | DB2 message formatting | `9999-FORMAT-DB2-MESSAGE` appends ` SQLCODE:` + `----9` edited code + DSNTIAC text, truncated to 75 chars. CTTU 9800 appends SQLERRM twice and has no space (`…first:SQLCODE :`) | Source literal + ` SQLCODE: <code>` with single spaces. No DSNTIAC/SQLERRM text. PostgreSQL SQLSTATE is logged server-side. Codes without a PG equivalent show `-999` | Stable, testable messages; no internal detail leaked |
| D-06 | 3270 attributes → HTML validation | ASKIP/PROT/UNPROT, FSET, IC, BRT/DRK, colours, cursor positioning (`-1` length), `*` in blank required fields | MUI `disabled`/`readOnly` (PROT), `autoFocus` (IC), `error` styling (red), `TableRow selected` (DFHNEUTR highlight), `maxLength` from BMS LENGTH, `*` placeholder for a blank key. Field edits run client-side for immediate feedback and again server-side with Bean Validation (`@TranTypeCode`, `@TranTypeDescription`), with identical strings | HTML idiom; server remains the authority |
| D-07 | Backward page with fewer than 7 earlier rows | 8100 treats SQLCODE +100 as an error (`Error on fetch Cursor C-TR-TYPE-BACKWARD`, Q4) | Returns page 1 (forward read). With no earlier row at all: page 1 + `No previous pages to display` | Avoid a spurious error after concurrent deletes |
| D-08 | Description padding | `DCL-TR-DESCRIPTION-LEN = LENGTH(field) = 50`, so DB2 stores descriptions right-padded to 50 (Q5) | Stored trimmed | VARCHAR semantics; comparisons and LIKE filters behave as users expect |
| D-09 | Max-length message | BMS fields are 50 bytes; overflow is impossible on a 3270 | New message `Transaction Desc must not exceed 50 characters.` (also UI `maxLength=50`) | APIs accept arbitrary input |
| D-10 | "No change" on CTLI update | `No change detected with respect to database values.` is shown but not an error: F10 still issues the UPDATE (1211) | UI shows the message on U+Enter as in the source, but F10 does not call the API when nothing changed; API returns `400 NO_CHANGE` | Avoid pointless writes |
| D-11 | After delete in CTLI | Screen is resent with the old rows, COMMAREA re-initialized; next Enter shows page 1 | Page 1 is reloaded immediately with info `HIGHLIGHTED row deleted.Hit Enter to continue` | No stale rows on screen |
| D-12 | F8 on the last page | First F8 shows the info `Type U to update…` and marks the last page shown; the second shows `No more pages to display` (2500) | `No more pages to display` on the first F8 | Simpler and clearer; same end message |
| D-13 | CTTU unreachable/unused source paths | `No input received` unreachable (Q7); `Selected transaction type shown above` unused; F6=Add label never active; state `V` unused | Not implemented (blank key → `Tran Type code must be supplied.` as the source actually behaves) | Dead code |
| D-14 | CTTU FK failure state | -532 leaves state `8` (falls back to the search prompt) | State `FAILED` (info `Changes unsuccessful`, key red), next key restarts at key entry | Consistent failure handling |
| D-15 | Authorization | No in-program check. Access is implied by the admin menu (COADM01C), and anyone who knows TRANID CTLI/CTTU can start them (Q11) | JWT bearer + Spring Security: `/api/transaction-types/**` requires role `ADMIN` (401 without token, 403 for user type `U`, message `No access - Admin Only option... `). UI `RequireAdmin` guard | Closes the gap; matches intended design |
| D-16 | Sign-on and admin menu | COSGN00C against USRSEC VSAM; COADM01C full menu | `/api/auth/login` against configured BCrypt users (ADMIN001/USER0001 sample). `/admin` is a placeholder menu with options 5/6 active and 1–4 marked "Not migrated" | Out of scope beyond what CTLI/CTTU need |
| D-17 | PF3 from CTTU | Returns to COADM01C even when started from CTLI (Q10) | Exit → `/admin` (same) | Preserved |
| D-18 | Locking | DB2 table-level locks (LOCKSIZE TABLE) → -911 on contention | PostgreSQL row locks with `lock_timeout` (default 5 s, `carddemo.db.lock-timeout`). Timeout/deadlock → `409 LOCK_CONFLICT` with the source message (`Deadlock. Someone else updating ? SQLCODE: -911` / `Could not lock record for update`) | Equivalent outcome, better concurrency |
| D-19 | Description filter | `LIKE '%x%'`, case-sensitive, `%`/`_` act as wildcards (Q12) | Same (no escaping), preserved deliberately | Parity |
| D-20 | VSAM / TRANEXTR dual storage | Base CardDemo reads TRANTYPE/TRANCATG from VSAM/PS files refreshed by `TRANEXTR` (DSNTIAUL extract) and `MNTTRDB2` batch updates DB2 | **Out of scope.** The new service owns only the PostgreSQL tables. No extract or sync is provided, so a consumer that still reads the VSAM copy diverges until a replacement extract or CDC feed exists | Per task scope. Flagged as a migration risk |
| D-21 | Priming query / plain-text exits | `9998-PRIMING-QUERY` + `SEND-LONG-TEXT` on DB2 unavailability | Spring health endpoint (`/actuator/health`). DB failures → `500 DB_ERROR` JSON | Platform idiom |
| D-22 | Screen header | TITLE01/02, date `mm/dd/yy`, time `hh:mm:ss`, TRNNAME, PGMNAME | Same values in `ScreenHeader` (client clock) | Parity |

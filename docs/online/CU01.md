# CU01 — Add User

Source: [COUSR01C](../../app/cbl/COUSR01C.cbl), map [COUSR01 / COUSR1A](../../app/bms/COUSR01.bms).
CA00 option 2 opens `/admin/users/add`. Enter calls `POST /api/admin/users`.

| COBOL paragraphs | Port and test trace |
|---|---|
| MAIN-PARA, RETURN-TO-PREV-SCREEN | Admin JWT, PF3 back to CA00; invalid AIDs use the COBOL message. API `MAIN_PARA_*` and UI CU01 test. |
| PROCESS-ENTER-KEY | First-name, last-name, user-ID, password, type required in source order; first error wins. API `CU01_PROCESS_ENTER_KEY_field_validation`, UI Enter validation. |
| WRITE-USER-SEC-FILE | Insert by user ID; duplicate conflict and normal response keep the COBOL messages. API `CU01_WRITE_USER_SEC_FILE_duplicate_and_signon` proves the new row authenticates through CC00. |
| SEND-USRADD-SCREEN, RECEIVE-USRADD-SCREEN, POPULATE-HEADER-INFO | Shared header, BMS field order/widths, password masking and PF keys. UI CU01 test. |
| CLEAR-CURRENT-SCREEN, INITIALIZE-ALL-FIELDS | PF4 and a successful add blank the form. UI CU01 test. |

**Deviations.** PF12 is printed on the BMS legend but falls through to the
invalid-key branch in COBOL; the web screen follows the program and does not
advertise PF12. ID and password use E2 normalization (uppercase and trailing
padding removed); names keep their case. The API rejects over-width and
control characters instead of relying on terminal field lengths. User type is
restricted to A/U by E2's schema. Passwords are BCrypt hashed on write and
never included in a read API or response. There is no schema or codec change.

# CU02 — Update User

Source: [COUSR02C](../../app/cbl/COUSR02C.cbl), map [COUSR02 / COUSR2A](../../app/bms/COUSR02.bms).
CA00 option 3 or CU00's U selection opens `/admin/users/update`. The latter
auto-fetches the selected user.

| COBOL paragraphs | Port and test trace |
|---|---|
| MAIN-PARA, RETURN-TO-PREV-SCREEN | Admin JWT; selected key from CU00 carries in browser route state. PF3 saves and returns to caller; PF12 exits to CA00 without saving. API `MAIN_PARA_*`; UI CU00 selection and CU02 PF3 tests. |
| PROCESS-ENTER-KEY, READ-USER-SEC-FILE | Enter fetches `GET /api/admin/users/record?userId=…`; key required, missing row uses the source error, successful read shows the PF5 prompt. API `CU02_CU03_PROCESS_ENTER_KEY_READ_USER_SEC_FILE_never_returns_password`; UI CU02 fetch. |
| UPDATE-USER-INFO, UPDATE-USER-SEC-FILE | PF5 saves via PUT on the same resource. Compare under a transaction/row lock during submit and reject no-op updates with the COBOL message. API `CU02_UPDATE_USER_INFO_UPDATE_USER_SEC_FILE_and_no_change` and UI CU02 PF5/PF3. |
| SEND-USRUPD-SCREEN, RECEIVE-USRUPD-SCREEN, POPULATE-HEADER-INFO, CLEAR-CURRENT-SCREEN, INITIALIZE-ALL-FIELDS | Render BMS fields and use shared header and PF keys. PF4 clears all form fields. UI CU00 selection and CU02 clear tests. |

**Deviations.** Unlike the terminal, the web API cannot redisplay the current
password. A blank replacement leaves the stored hash unchanged; a nonblank
replacement uses the same rules as [CU01](CU01.md). The database lock lasts
only for the update request, not for the screen interaction. PF3 exits on a
successful or unchanged save, but displays genuine save errors rather than
hiding them while returning to the caller.
Role/password changes affect future sign-ons; already issued E2 JWTs remain
valid until expiry.

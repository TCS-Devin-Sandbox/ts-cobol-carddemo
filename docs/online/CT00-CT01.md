# E6 — CT00 transaction list / CT01 transaction view

Sources: `app/cbl/COTRN00C.cbl`, `COTRN01C.cbl`, `app/bms/COTRN00.bms`,
`COTRN01.bms`, and corresponding `app/cpy-bms` layouts. No estate changes.

## Data and routing

The schema is **already available**: `OnlineApplication.migrateOnlineSchemas`
runs the B3 migration from `classpath:db/vsam`, copied by the existing Maven
resource entry from `java/common`, with independent `flyway_vsam_schema_history`.
No additional migration, copied DDL, or compose changes are necessary. E4/E5
can use the same existing tables. The DB2-derived migration history is separate.

Authenticated USER and ADMIN JWT sessions can read `/api/transactions?startKey=`
and `/api/transactions/view?transactionId=`. These are read-only operations.
JSON uses B3 business column names, not copybook identifiers. List responses
contain rows, pageNumber, message; view responses contain transaction, message.
The list uses a keyset query and eleven-row lookahead, displaying ten rows.
Menu options 6 and 7 route to `/transactions` and `/transactions/view`.
Select S/s in a row and press Enter to view; direct entry is supported.

## Preserved quirks and deviations

* PF7/PF8 preserve first/last key boundaries without repeating the boundary
  record. MAIN-PARA resets NEXT-PAGE-NO, but then restores CARDDEMO-COMMAREA,
  including CDEMO-CT00-NEXT-PAGE-FLG. Thus the previous lookahead survives.
  First-page PF7 and last-page PF8 show the distinct already-at-boundary texts.
  HTTP carries direction, startKey and pageNumber in place of browse state.
* A final exactly-full page still shows the bottom message: the eleventh read
  reaches ENDFILE. No records at/after a search key produces STARTBR's distinct
  `You are at the top of the page...` text rather than a not-found message.
* Only the first nonblank selection is considered. S and s are accepted.
  Invalid selection does not stop the subsequent browse; a browse error or
  end-of-file message can overwrite the selection error.
* CT00 requires all sixteen search positions to be numeric. CT01 does not
  perform a numeric check: alphabetic input is looked up and can be not found.
* List descriptions are truncated to 26 positions; dates use MM-DD-YY;
  both screens' amounts use signed, zero-filled PIC +99999999.99 display,
  discarding an overflowing ninth integer digit without changing stored data.
* CT01 blank input preserves previous detail; a nonblank failed lookup clears
  detail. PF4 clears input, detail and message. PF3 returns to the list if
  entered from there, otherwise the menu; PF5 browses from CT01.
* JWT replaces identity COMMAREA; route state carries the selected key and
  caller. Browser navigation replaces XCTL. React renders SEND/RECEIVE and
  shared ScreenHeader renders the titles/clock. Terminal color/erase/cursor
  control is represented by messages, controlled fields and initial focus.
* CT01's READ UPDATE obtains no lock in this port: it never writes a record,
  and holding a database lock across HTTP requests would be inappropriate.
* SQL exceptions retain the source's capitalization-sensitive lookup messages;
  database exception details are not disclosed. Read response errors use
  message payloads rather than HTTP error status, like terminal redisplay.

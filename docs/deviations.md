# Deviations from the COBOL source (CTLI / CTTU)

Functional equivalence with `COTRTLIC.cbl` / `COTRTUPC.cbl` is the acceptance criterion. The items below are the only intentional differences; each lists the source behaviour, the target behaviour and why.

| ID | Area | Source (COBOL / CICS / BMS) | Target (API / React) | Rationale / impact |
|---|---|---|---|---|
| D-01 | PF keys → buttons | 3270 AID keys ENTER, PF2, PF3, PF4, PF5, PF7, PF8, PF10, PF12 (PF13–24 fold to PF1–12 via CSSTRPFY); labels on BMS row 24 | One button per key with the exact BMS label (`F2=Add`, `F3=Exit`, `F7=Page Up`, `F8=Page Dn`, `F10=Save`, `ENTER=Process`, `F4=Delete`, `F5=Save`, `F12=Cancel`); the physical F-keys and Enter are also bound. Buttons whose BMS label is dark are not rendered. PF13–24, CLEAR, PA1/PA2 are not mapped | Browser has no AID keys. CTLI treats unmapped keys as ENTER and CTTU rejects them with 'Invalid key pressed' — reproduced for F-keys pressed on the keyboard |
| D-02 | COMMAREA → stateless cursor | CTLI keeps first/last key, screen number, next-page flag, last-page-shown flag, row data and pending action in the COMMAREA (`RETURN TRANSID('CTLI') COMMAREA`); CTTU keeps `TTUP-CHANGE-ACTION` and old/new values | API is stateless: `cursor`, `direction`, `page`, `typeFilter`, `descFilter` query parameters; response returns `firstKey`, `lastKey`, `nextCursor`, `hasNext`, `hasPrev`, `pageNumber`. Pending row action, last-page-shown flag and the CTTU state live in React component state | REST statelessness. `nextCursor` carries the look-ahead key that the source stores in `WS-CA-LAST-TR-CODE`, so the forward predicate `TR_TYPE >= key` is unchanged. Browser refresh loses the pending action / CTTU state (equivalent to CLEAR on 3270) |
| D-03 | CTTU upsert semantics | F5 runs `UPDATE`; on SQLCODE +100 runs `INSERT` (9600 → 9700). No separate "create" statement; -803 only possible on a race | `PUT /api/transaction-types/{trType}` (default `upsert=true`) reproduces UPDATE-then-INSERT (200 updated / 201 inserted). `POST` is an explicit INSERT (409 `DUPLICATE_KEY` on -803). CTLI inline update uses `PUT ?upsert=false` (UPDATE only, +100 → 404 'Record not found. Deleted by others ? ') | One resource, two source paragraphs (9200 vs 9600) with different +100 behaviour; the UI chooses the source-equivalent mode per screen |
| D-04 | 3270 attributes → HTML validation | BMS `LENGTH`, `PROT/ASKIP/UNPROT`, `IC`, program-set colour (red), `DRK`, MDT/FSET; COBOL edits in 1210/1220/1230/1240/1245 | `maxLength`, `readOnly`/`disabled`, `autoFocus`, MUI `error` state, buttons not rendered; identical edits in `src/validation.ts` (client) and Bean Validation / `@TranTypeCode` (server) with the same literals. The server additionally rejects descriptions > 50 chars with 'Transaction Desc can have numbers or alphabets only.' (impossible on 3270) | HTML has no field attributes; server re-validates because the API is callable directly. `*` echo of blank required fields is replaced by the red error state |
| D-05 | VSAM sync out of scope | `jcl/TRANEXTR.jcl` unloads the DB2 tables (DSNTIAUL) to `TRANTYPE.PS` / `TRANCATG.PS` used to rebuild VSAM files read by the base CardDemo batch; batch maintenance `MNTTRDB2` / `COBTUPDT` | Not implemented. PostgreSQL is the only store | Divergence risk: any consumer of the VSAM TRANTYPE/TRANCATG files will not see changes until an equivalent extract is built |
| D-06 | Security | Admin-only by menu routing (COSGN00C → COADM01C for user type 'A'); CSD `RESSEC(NO)`; programs do not check user type | Spring Security session, `ROLE_ADMIN` enforced on every `/api/transaction-types/**` call (401 anonymous, 403 non-admin); CSRF cookie/header | Stronger than source; required because REST endpoints are directly addressable |
| D-07 | Paging from a stale key | 8100 FETCH +100 before 7 rows → 'Error on fetch Cursor C-TR-TYPE-BACKWARD'; a forward re-read from a key after which no (matching) rows remain shows an empty page with the old screen number | Both cases return page 1 (forward from the lowest key); 'No records found…' messages only when nothing matches at all | Graceful recovery when rows were deleted or edited out of the filter (e.g. after an inline update or another user's delete); unreachable with unchanged data |
| D-08 | SQL error text | Messages append `SQLERRM` / DSNTIAC text after the SQLCODE | API returns `{code, message, sqlcode}`; the UI composes the source STRING format (`PIC ----9` SQLCODE) without SQLERRM. PostgreSQL SQLSTATEs are mapped to DB2 SQLCODEs (23503→−532, 23505→−803, 40P01/40001/55P03→−911) | DB2 message tokens have no PostgreSQL equivalent |
| D-09 | DB2 priming query | CTLI runs `SELECT 1 FROM SYSIBM.SYSDUMMY1` and shows 'Db2 access failure. ' full-screen | Connection failures map to 500 'Error accessing: TRANSACTION_TYPE table. SQLCODE:' shown on the error line | Connection pooling replaces per-task thread priming |
| D-10 | Sign-on / admin menu | COSGN00C (USRSEC VSAM) and COADM01C with 6 options | `/login` (in-memory users `admin`/`user`; passwords required, development defaults only in the `local` profile) and `/admin` placeholder listing the COADM02Y options; only options 5 and 6 navigate | Security module is out of scope; placeholder keeps the navigation contract (F3 from CTLI/CTTU returns to CA00) |
| D-11 | CTTU type-code numeric edit | `FUNCTION TEST-NUMVAL` accepts signs/decimal points (e.g. `1.`) | Accepts 1–2 digits only; anything else → 'Tran Type code must be numeric.' | Signed/decimal forms are not meaningful type codes; messages unchanged |
| D-12 | Concurrency | DB2 locks held only within a task; no optimistic check ('Record changed by some one else. Please review' is never set) | One DB transaction per request; no version column; lock failures → 409 `LOCK_ERROR` (−911 messages) | Same last-writer-wins behaviour as source |

## Source behaviours reproduced on purpose (not deviations)

- CTTU SHOW-DETAILS displays 'Enter transaction type to be maintained' (shared `WHEN` in 3250).
- CTTU after a −532 delete failure stays in START-DELETE; the next ENTER re-edits with a blank description and reports 'Transaction Desc must be supplied.' (protected field not transmitted by the 3270).
- CTLI 'Please select only 1 action' takes precedence over 'Action code selected is invalid'.
- CTLI description filter is case-sensitive `LIKE '%x%'`; `%`/`_` typed by the user act as wildcards (no escaping in source).
- Seed value `REVERAL` (type 06) kept verbatim.

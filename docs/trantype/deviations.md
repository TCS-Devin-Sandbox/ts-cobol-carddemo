# Phase 6 — Deviations from the source

Each entry gives the source behaviour (with paragraph), the modern behaviour, and the reason. Requirement IDs refer to `requirements-ctli-cttu.md`.

| ID | Area | Source (COBOL / CICS / DB2) | Modern | Rationale |
|---|---|---|---|---|
| D-01 | PF keys → buttons | 3270 AID keys Enter/PF2/PF3/PF4/PF5/PF7/PF8/PF10/PF12 (YYYY-STORE-PFKEY folds PF13–24 to PF1–12) | Clickable `FunctionKeyBar` buttons plus `useFunctionKeys` bindings: CTLI Enter/F2/F3/F7/F8/F10; state-valid CTTU Enter/F3/F4/F5/F12. Invalid CTTU buttons are hidden; CTLI F10 is disabled without a pending action. Mapped repeat events are suppressed while preventing browser defaults. Single Enter on interactive controls keeps native activation; repeated Enter there is prevented. PF13–24 are not mapped | Browser UX; F-key parity kept for power users |
| D-02 | COMMAREA → stateless cursor params | CTLI keeps first/last key, page number, next-page flag, pending action and the displayed rows in the COMMAREA between `RETURN TRANSID` | Stateless `cursor`, `direction=FORWARD/BACKWARD`, `size`, `page` and filters. Response: `rows`, `firstKey`, `lastKey`, `nextCursor`, `hasNext`, `hasPrev`, `pageNumber`, `message`. The UI supplies the page label; service returns 1 without earlier rows, otherwise max(page,2). It is not count-derived and does not wrap after 9. Pending actions and CTTU state live in React state | REST statelessness; horizontal scaling |
| D-03 | CTTU upsert semantics | F5 save always runs `UPDATE` then `INSERT` on SQLCODE +100 (9600 → 9700), for both edit and add | `PUT /{trType}` saves (lookup then update or insert), returning 200/201. CTTU uses PUT for both edit and add, with no `upsert` query parameter. CTLI uses strict `PATCH /{trType}` (404 when absent). `POST` is a separate insert-only API/client operation; CTTU does not call it | Keep CTTU save/upsert separate from CTLI strict update; POST exposes explicit insertion |
| D-04 | Duplicate-key message | 9700 builds `Error inserting record into: TRANSACTION_TYPE Table. SQLCODE:` + the **stale** SQLCODE of the preceding UPDATE (`100`) + SQLERRM (Q6) | `409 DUPLICATE_KEY` `Error inserting record into: TRANSACTION_TYPE Table. SQLCODE:-803` | Report the real DB2-equivalent code; SQLERRM text is DB-specific |
| D-05 | DB2 message formatting | `9999-FORMAT-DB2-MESSAGE` appends ` SQLCODE:` + `----9` edited code + DSNTIAC text, truncated to 75 chars. CTTU 9800 appends SQLERRM twice and has no space (`…first:SQLCODE :`) | Preserves endpoint-specific literal spacing (see `target-spec.md` §3.3), without DSNTIAC/SQLERRM. Generic data-access errors use `Error accessing: TRANSACTION_TYPE table. SQLCODE: SQLSTATE <state>` (or `null`); SQLSTATE is exposed in this message and the exception is logged | Stable endpoint-specific messages; generic errors retain SQLSTATE |
| D-06 | 3270 attributes → HTML validation | ASKIP/PROT/UNPROT, FSET, IC, BRT/DRK, colours, cursor positioning (`-1` length), `*` in blank required fields | MUI disabled fields, autoFocus, error styling, TableRow selected and maxLength implement the browser equivalents. No `*` placeholder or field-level server-error focus mapping. `@TranTypeCode` / `@TranTypeDescription` delegate through `TranTypeRules` to `TransactionTypeEdits`; UI mirrors field edits. Literal `*` fails syntax rather than being treated as missing | HTML idiom; server remains the authority |
| D-07 | Backward page with fewer than 7 earlier rows | 8100 treats SQLCODE +100 as an error (`Error on fetch Cursor C-TR-TYPE-BACKWARD`, Q4) | Returns only the earlier rows in ascending order, even if fewer than 7; no forward-page fallback. No earlier rows returns an empty page and `No more pages for these search conditions`. UI F7 on a page with hasPrev=false makes no request and reports `No previous pages to display` | Avoid a spurious error after concurrent deletes |
| D-08 | Description padding | `DCL-TR-DESCRIPTION-LEN = LENGTH(field) = 50`, so DB2 stores descriptions right-padded to 50 (Q5) | Stored trimmed | VARCHAR semantics; comparisons and LIKE filters behave as users expect |
| D-09 | Max-length message | BMS fields are 50 bytes; overflow is impossible on a 3270 | New message `Transaction Desc must not exceed 50 characters.` (also UI `maxLength=50`) | APIs accept arbitrary input |
| D-10 | "No change" on CTLI update | `No change detected with respect to database values.` is shown but not an error: F10 still issues the UPDATE (1211) | U+Enter stages the update; F10 validates and reports no change without a write. API PATCH also returns `400 NO_CHANGE` | Avoid pointless writes |
| D-11 | After delete in CTLI | Screen is resent with the old rows, COMMAREA re-initialized; next Enter shows page 1 | Page 1 is reloaded immediately with info `HIGHLIGHTED row deleted.Hit Enter to continue` | No stale rows on screen |
| D-12 | F8 on the last page | First F8 shows the info `Type U to update…` and marks the last page shown; the second shows `No more pages to display` (2500) | `No more pages to display` on the first F8 | Simpler and clearer; same end message |
| D-13 | CTTU unreachable/unused source paths | `No input received` unreachable (Q7); `Selected transaction type shown above` unused; F6=Add label never active; state `V` unused | UI blank search key shows `No input received`; blank API key gives `Tran Type code must be supplied.`. Unused source message, F6 label and V state are not implemented. Unbound keys are ignored instead of reporting `Invalid key pressed` | Current UI handles blank input explicitly; unused source paths omitted |
| D-14 | CTTU FK failure state | -532 leaves state `8` (falls back to the search prompt) | State `DELETE_FAILED`, info `Changes unsuccessful`; key entry is enabled immediately. The key is not specially colored red; Enter looks up the current key | Consistent failure handling |
| D-15 | Authorization | No in-program check. Access is implied by the admin menu (COADM01C), and anyone who knows TRANID CTLI/CTTU can start them (Q11) | JWT bearer + Spring Security: transaction-type routes require `ADMIN` (401 without token, 403 for role `USER`, message `Access restricted to administrators`). UI `RequireAdmin` redirects missing/non-admin sessions to `/login`; login rejects non-admin sessions with that message | Closes the gap; matches intended design |
| D-16 | Sign-on and admin menu | COSGN00C against USRSEC VSAM; COADM01C full menu | Superseded by [E2 sign-on and menus](../online/signon-menus.md): USRSEC table, CC00/CM00/CA00, JWT COMMAREA claims | E2 |
| D-17 | PF3 from CTTU | Returns to COADM01C even when started from CTLI (Q10) | F3 → `/transaction-types` when launched with `?from=list`; otherwise `/admin` | Preserve the caller's navigation context |
| D-18 | Locking | DB2 table-level locks (LOCKSIZE TABLE) → -911 on contention | PostgreSQL row locks; Hikari `connection-init-sql` sets lock_timeout from `${carddemo.db.lock-timeout:5s}`. PATCH timeout/deadlock → `409 LOCK_ERROR`, `Deadlock. Someone else updating ?`; PUT → `409 LOCK_ERROR`, `Could not lock record for update`. Integration test overrides timeout to 1s and tests both against a held row lock | Equivalent outcome, better concurrency |
| D-19 | Description filter | `LIKE '%x%'`, case-sensitive, `%`/`_` act as wildcards (Q12) | Same (no escaping), preserved deliberately | Parity |
| D-20 | VSAM / TRANEXTR dual storage | Base CardDemo reads TRANTYPE/TRANCATG from VSAM/PS files refreshed by `TRANEXTR` (DSNTIAUL extract) and `MNTTRDB2` batch updates DB2 | **Out of scope.** The new service owns only the PostgreSQL tables. No extract or sync is provided, so a consumer that still reads the VSAM copy diverges until a replacement extract or CDC feed exists | Per task scope. Flagged as a migration risk |
| D-21 | Priming query / plain-text exits | `9998-PRIMING-QUERY` + `SEND-LONG-TEXT` on DB2 unavailability | Actuator dependency and public `/actuator/health` (also subpaths permitted). `healthIsPublic` checks unauthenticated 200/UP. Generic data-access failures → `500 DB_ERROR` JSON; mapped conflicts retain 409 | Platform idiom |
| D-22 | Screen header | TITLE01/02, date `mm/dd/yy`, time `hh:mm:ss`, TRNNAME, PGMNAME | `ScreenHeader` shows CardDemo banner, Maintain Transaction Type title, transaction/program ids and client date/time at render. Date/time use browser locale, not fixed source formatting | Browser-local header rendering |
